개념 1 생성형 AI(Generative AI) & LLM(초거대 언어 모델)

• 생성형 AI: 기존 검색 엔진처럼 '찾아주는' 것을 넘어, 질문에 맞춰 새로운 글, 그림, 웹페이지 코드를 '스스로 창작'해내는 인공지능입니다.
• LLM (Large Language Model): 수천억 개의 책과 웹 문서, 프로그래밍 코드를 미리 읽고 학습하여 인간처럼 문맥을 이해하고 유창하게 한국어로 대화하는 '초거대 두뇌 모델'입니다.

개념 2 바이브 코딩 (Vibe Coding)이란?

"문법을 외우지 말고 느낌(Vibe)과 목적을 설명하세요!"
개발자가 프로그래밍 언어를 직접 한 줄 한 줄 타이핑하던 과거와 달리, 내가 원하는 화면의 느낌, 테마 색상, 사용자 경험을 일상적인 우리말로 말하면 AI가 실제 구현 코드를 대신 작성해 주는 혁신적인 협업 방식입니다.

개념 3 클로드 가입 & 데스크톱 앱(Desktop App) 설치

• 가입 및 로그인: claude.ai 접속 후 구글 계정으로 3초 만에 원클릭 로그인합니다.
• 데스크톱 전용 앱 설치: 웹 브라우저 탭 속에 묻히지 않고 내 컴퓨터에 전용 앱을 설치해 작업합니다.
• 브라우저 vs 데스크톱 앱 차이: 웹 브라우저는 탭이 닫히면 번거롭지만, 데스크톱 앱은 전용 단축키(Option+Space / Alt+Space)로 언제든 즉시 소환되고 컴퓨터 화면 캡처 연동이 훨씬 빠르고 편리합니다.

개념 4 클로드 화면 둘러보기 (주요 UI 명칭과 용도)

개념 6 AI와 대화의 5대 작동 원리 (세션 · 토큰 · 컨텍스트 윈도우 · 메모리)
1) 세션 (Session)이란?

하나의 독립된 대화방을 뜻합니다. 주제가 바뀌면 반드시 [New Chat]을 열어 새 세션으로 시작해야 AI가 이전 주제와 문맥을 헷갈리지 않습니다.

2) 앞 대화를 아는 원리

AI는 사람처럼 뇌에 기억을 새겨두는 것이 아닙니다! 우리가 새 질문을 할 때마다 지금까지 나눈 이전 대화 전체를 0.1초 만에 한꺼번에 다시 읽고 답변을 생성합니다.

3) 토큰 (입력 vs 출력)

AI가 글을 읽고 쓰는 최소 단위(글자 조각)입니다. 내가 건넨 질문과 이전 대화 기록을 입력 토큰, AI가 써준 답변을 출력 토큰이라고 부릅니다.

4) 컨텍스트 윈도우 한계

AI의 '작업 기억 책상 크기'입니다. 대화가 너무 길어지면 책상이 꽉 차서 가장 오래된 대화부터 시야 밖으로 밀려나 앞 내용을 잊어버리게 됩니다.

💡 메모리(Memory) & 프로젝트(Projects)로 세션 넘기억하기: 새 대화창을 열어도 "항상 초보자용 한글 주석을 달아줘", "단일 index.html로 작성해줘"와 같은 나의 선호 규칙을 AI가 영구히 기억하도록 지침을 저장해 두는 기술입니다.
개념 7 클라우드란? & 클라우드 컴퓨터 vs 내 컴퓨터

• 클라우드 컴퓨터: 24시간 인터넷 하늘에 떠 있는 글로벌 대형 데이터센터의 거대한 슈퍼컴퓨터입니다.
• 내 컴퓨터: 지금 내 손가락 아래에 있는 물리적인 노트북과 데스크톱 PC입니다.
• 왜 어디서나 같은 대화가 보일까?: 대화 내용이 내 컴퓨터 하드디스크가 아니라 인터넷 클라우드 서버에 안전하게 보관되기 때문입니다. 스마트폰이든 다른 컴퓨터든 로그인만 하면 1초 만에 똑같이 대화가 이어집니다!

개념 8 클로드 챗(Chat) · 코드(Code) · 코워크(Co-work)

• 클로드 챗 (Claude Chat): 브라우저와 앱에서 일상 대화로 질의응답하는 가장 대중적인 기본 환경.
• 클로드 코드 (Claude Code): 개발자의 터미널에서 로컬 컴퓨터의 파일과 Git을 직접 제어하는 차세대 도구.
• 클로드 코워크 (Claude Co-work): 화면을 공유하며 사람과 AI가 한 화면에서 협업하는 기능.
💡 최신 트렌드: 현재 챗과 코워크가 유기적으로 하나로 합쳐지는 중이며, 대화창 옆에서 완성된 웹 화면을 바로 조작하고 다듬는 일체형 워크스페이스로 진화하고 있습니다.

개념 9 클로드 2대 핵심 무기: 아티팩트(Artifacts) & 프로젝트(Projects)

• 아티팩트 (Artifacts): 완성된 웹페이지나 게임 코드를 우측 별도 창에 정갈하게 분리하여 실시간 Preview(화면 테스트)와 Code(코드 확인), 그리고 내 컴퓨터로 Download(다운로드)할 수 있게 해주는 기능입니다.
• 프로젝트 (Projects): 수업이나 특정 업무 전용 폴더를 만들고 참고 문서와 맞춤 지침을 등록하여 대화가 길어져도 한결같은 기억력과 전문성을 유지하는 전용 작업실입니다.

개념 1 Git과 GitHub의 결정적 차이 & 저장소(Repository)

• 저장소 (Repository / 레포): 프로젝트 단위의 전용 금고 폴더. Public(전 세계 공개) 또는 Private(비공개)로 범위를 정합니다.

개념 4 AI로 Git과 GitHub를 관리하는 두 가지 방법
방법 1: 플러그인(커넥터)으로 AI와 GitHub 직접 연결
클로드 설정에서 GitHub 연동을 승인하여, AI가 내 저장소의 파일을 직접 읽고 커밋할 수 있도록 권한을 주는 방법.
방법 2: 플러그인 없이 터미널 CLI(GitHub CLI)로 관리하기
AI에게 "방금 만든 코드를 올릴 Git 명령어를 알려줘"라고 묻고, 복사한 명령어를 내 컴퓨터 터미널에서 직접 실행하는 깔끔하고 강력한 방법.
개념 5 Git 핵심 4대 영역 흐름 (작업폴더 ➔ 깃로그)
• 1. 작업 폴더 (Working Tree): 현재 내 컴퓨터에서 작업 중인 실제 파일들.
• 2. 스테이징 영역 (Staging Area): 이번 커밋에 담을 파일만 골라 담는 '장바구니' (git add).
• 3. 커밋 (Commit): 장바구니에 담긴 내역을 영구 장부에 도장 찍고 확정 (git commit).
• 4. 깃 로그 (Git Log): 지금까지 찍힌 모든 커밋 도장들의 타임라인 기록 (git log).
개념 6 사용자 지정 기능 3종 세트: 스킬(Skills) · 커넥터(Connectors) · 플러그인(Plugins)
1) 스킬 (Skills)

모바일 반응형 검수, 폼 유효성 검사, 깃 커밋 등 자주 쓰는 복잡한 검수 지침을 단축어(예: [스킬명 적용해줘])로 즉시 소환하는 규칙 도구입니다.

2) 커넥터 (Connectors)

구글 드라이브, 노션, 깃허브 등 외부 서비스와 클로드를 안전하게 연결하여 외부 데이터를 실시간으로 읽어오는 다리 역할입니다.

3) 플러그인 (Plugins)

스킬, 커넥터, 맞춤 도구를 하나로 묶어 클릭 한 번으로 설치해 클로드의 능력을 극대화하는 종합 확장 부품입니다.

단계별 핵심 실습
실습 1

AI에게 Git을 맡겨 저장소 초기화와 커밋 만들기

내 컴퓨터 폴더에서 Git 저장소를 만들고, 상태 확인(status), 변경점 비교(diff), 스테이징(add) 및 첫 커밋(commit)을 완성합니다.

💻 실행할 핵심 터미널 명령어 흐름:
# 1. 내 프로젝트 폴더에서 Git 타임머신 가동
git init
# 2. 현재 상태 확인 (빨간색으로 추적 안 된 파일 확인)
git status
# 3. index.html 파일을 장바구니(스테이징)에 담기
git add index.html
# 4. 첫 번째 저장 도장 쾅! (커밋)
git commit -m "feat: 첫 번째 웹페이지 파일 커밋"
💬 AI 요청 프롬프트 (Git 명령어 자문) 
당신은 친절한 Git 튜터입니다.
내 컴퓨터 폴더에 1회차에서 만든 index.html 파일이 있습니다.
1. Git 저장소를 처음 시작하고 상태를 확인하는 명령어(git status)를 알려주세요.
2. 파일의 작은 변경을 만들었을 때 무엇이 바뀌었는지 확인하는 diff 명령어를 설명해주세요.
3. 스테이징(add)하고 "feat: 베이커리 랜딩페이지 첫 커밋"이라는 메시지로 커밋하는 과정을 왕초보 눈높이에서 3줄로 설명해주세요.
실습 2

변경을 나누고 브랜치(Branch)와 이전 시점 살펴보기

기능 브랜치를 만들어 독립적으로 작업하고, 커밋 그래프(git log)로 타임머신을 확인한 뒤 안전하게 병합하거나 실수했을 때 되돌립니다.

🌿 브랜치 생성부터 되돌리기까지 터미널 흐름:
# 1. 새 기능 브랜치 생성 및 이동
git checkout -b feature/dark-mode
# 2. 브랜치에서 수정한 뒤 별도 커밋으로 저장
git commit -am "feat: 다크모드 스타일 추가"
# 3. 커밋 그래프와 이전 시점 타임라인 한 줄로 확인
git log --oneline --graph
# 4. main 브랜치로 돌아와서 기능 병합
git checkout main && git merge feature/dark-mode
# 5. [꿀팁] 방금 커밋을 안전하게 취소하고 이전으로 되돌릴 때
git revert HEAD
💬 AI 요청 프롬프트 (브랜치 및 롤백 질문) 
Git에서 원본 코드를 건드리지 않고 새로운 실험을 위해 브랜치(Branch)를 만드는 이유를 일상 비유로 설명해주세요.
그리고 다음 3가지를 초보자용 명령어로 알려주세요:
1. 'feature/new-design'이라는 새 나뭇가지 브랜치 만드는 법
2. 작업 완료 후 main 브랜치에 합치는(merge) 법
3. 실수로 코드를 잘못 수정했을 때 어제 상태로 안전하게 되돌리는(revert) 법
실습 3

반복 가능한 깃 스킬(Git Skills) 만들기 & AI에게 반복 작업 맡기기

💬 클로드 반복 깃 스킬 등록 프롬프트

내가 앞으로 대화창에 "[깃 커밋 스킬 적용해줘]"라고 요청하면, 다음 3단계를 자동으로 수행해주세요:

1. 변경된 코드의 핵심 목적을 파악하여 한글 커밋 메시지를 추천 (예: 'feat: 네비게이션 메뉴 추가')
2. 실행할 git add 및 git commit 터미널 명령어를 코드 블록으로 제공
3. 초보자가 실수하지 않도록 현재 상태 점검 팁 1줄 안내

위 스킬을 도구함에 등록했음을 확인해주세요.
실습 4

깃 저장소 만들고 프로젝트 올리기 (`git push`) & 파일 최종 점검

깃허브에 원격 저장소를 생성하고 .gitignore로 불필요한 파일을 걸러낸 뒤, git push로 인터넷 클라우드에 안전하게 보관합니다.

🚀 깃허브 푸시 4단계 흐름:
1. GitHub에서 [New repository]를 누르고 이름(예: my-web), Public을 선택해 저장소를 만듭니다. (또는 gh repo create 사용)
2. 공개소 올린 파일 최종 점검: 비밀번호나 개인정보, 불필요한 파일이 올라가지 않도록 .gitignore 파일을 확인합니다.
3. 내 컴퓨터 저장소와 깃허브 원격 주소를 연결합니다: git remote add origin https://github.com/내아이디/my-web.git
4. 원격 저장소로 내 코드를 쏘아 올립니다: git push -u origin main
실습 5

다른 컴퓨터에서 내려받아(Clone / Pull) 이어서 작업하기

학습관 컴퓨터에서 작업한 내용을 집 컴퓨터에서 git clone으로 그대로 복제해 오고, 수정된 최신 내용을 git pull로 당겨옵니다.

🔄 다른 컴퓨터에서 이어서 작업하는 2가지 마법 명령어:
# 1. 새 컴퓨터에서 통째로 최초 복제해 오기 (클론)
git clone https://github.com/내아이디/my-web.git
# 2. 다른 곳에서 수정한 최신 변경사항만 쏙 당겨오기 (풀)
git pull origin main
실습 6

GitHub Pages로 웹사이트 전 세계 공개하고 내 주소 확인하기

내가 만든 index.html을 전 세계 누구나 스마트폰과 PC로 접속할 수 있는 무료 웹사이트 주소로 배포하고 확인합니다.

🌐 GitHub Pages 무료 배포 4단계:
1. 깃허브 내 저장소 상단 메뉴의 [Settings(설정)] 탭을 클릭합니다.
2. 왼쪽 사이드바 메뉴에서 [Pages]를 클릭합니다.
3. Branch 설정에서 `main` 브랜치를 선택하고 [Save] 버튼을 누릅니다.
4. 약 1분 뒤 상단에 생성된 인터넷 주소(https://아이디.github.io/저장소명)를 확인하고 스마트폰으로 열어보세요!
💡 배포된 내 웹사이트를 동기들과 공유하세요!

특징: 응답 지연 없이 0.5초 만에 답변이 쏟아집니다. 가벼운 일상 질문이나 단순 텍스트 처리에 매우 경제적입니다.

3 아티팩트(Artifacts) 우측 창 활용

클로드에게 웹페이지 작성을 요청하면 화면 우측에 분할 창(Artifact)이 자동으로 열립니다. Preview에서 즉시 클릭 테스트하고, Code에서 완성된 코드를 확인합니다.

4 내 컴퓨터로 index.html 저장

우측 아티팩트 창 오른쪽 아래의 [Download(다운로드)] 버튼을 누르면 내 컴퓨터 바탕화면 폴더에 index.html로 저장되어 인터넷이 끊겨도 언제든 더블클릭으로 열 수 있습니다.

5 좋은 프롬프트 3요소 공식

목적(Goal): "빵집 랜딩페이지를 단일 HTML로 만들어주세요."
제약(Constraint): "초보자용 한글 주석을 달고 아티팩트로 보여주세요."

웹앱 (Web App / 웹 애플리케이션)

내 기기 안방 서재

비유: '외부와 차단된 내 집 안방 서재 책상'

인터넷 대화의 기본
서버와 클라이언트 (Server & Client)

비유: '식당의 주문하는 손님(클라이언트)과 맛있는 요리를 내어주는 주방장(서버)'
우리가 브라우저에서 버튼을 누르고 주소를 입력하는 행위는 손님(Client)의 '주문'이며, 저 멀리 인터넷 세상의 24시간 켜진 컴퓨터(Server)가 요청에 맞는 웹페이지와 데이터를 조리해 내 화면에 배달해 줍니다.

한눈에 비교 1 웹(Web) vs 앱(App) vs 웹앱(Web App) 차이점
• 웹 (Web): 정보 열람 중심의 읽는 사이트 (예: 네이버 뉴스, 포털 블로그)
• 앱 (App): 앱스토어에서 내 기기로 '직접 다운로드 설치'하여 쓰는 프로그램 (예: 카카오톡 앱, 은행 앱)
• 웹앱 (Web App): 설치 전혀 없이 링크 클릭만으로 앱처럼 계산하고 저장하는 진화된 웹! (우리 수업 목표)
한눈에 비교 2 로컬(Local) vs 클라우드(Cloud) 차이점
• 로컬 (Local): 오직 '내 컴퓨터 안'에만 저장된 상태 (예: 바탕화면 index.html 더블클릭 실행). 컴퓨터를 끄면 남들은 못 봄
• 클라우드 (Cloud): 인터넷 '24시간 가상 서버'에 저장된 상태 (예: Vercel 배포, Supabase DB). 전 세계 누구나 24시간 접속 가능
💡 수업 꿀팁: 1회차에는 내 컴퓨터(로컬)에서 만들고, 2회차부터 클라우드(Vercel)에 올려 가족·동기들에게 링크를 보냅니다!

비유: '화면 위에 둥둥 뜨는 안내 스티커'
새 페이지로 이동하지 않고, 현재 화면 위에 배경을 어둡게 깔고 팝업 형태로 나타나 상세 정보나 사진을 보여주는 윈도우 창.

테마 5

☁️ 클라우드 & 실시간 데이터베이스 (Supabase)

인터넷 금고
클라우드 데이터베이스 (Cloud DB)

비유: '언제 어디서든 열어보는 인터넷 중앙 금고'
내 컴퓨터 안의 임시 메모가 아니라 인터넷 서버에 저장되어, 크롬에서 쓴 글이 내 스마트폰 사파리에서도 1초 만에 똑같이 보이는 기술.

무료 BaaS
수퍼베이스 (Supabase)

비유: '클릭 몇 번으로 완성되는 무료 백엔드 스마트 레고'
복잡한 서버 구축 코딩 없이, 클릭만으로 데이터베이스와 사용자 인증, 실시간 통신 서버를 한 번에 무료 구축해주는 최신 클라우드 도구.

서비스형 백엔드
BaaS (Backend-as-a-Service)

비유: '서버 관리자를 대신 파견해주는 전문 관리 용역'
개발자가 직접 서버를 설치하고 보안을 관리할 필요 없이, 이미 완성된 서버 인프라를 대여해 프론트엔드 화면 제작에만 집중하게 돕는 서비스.

주문 창구
API (인터페이스 창구)

비유: '식당 주방과 손님을 이어주는 친절한 주문 카운터'
내 웹사이트가 클라우드 DB나 날씨 서버, 지도 서비스와 정해진 규칙대로 대화하고 데이터를 주고받을 수 있게 해주는 공식 통로.

디지털 출입증
API 키 (Anon Key & Secret Key)

비유: '클라우드 금고에 들어가는 공식 비밀번호 카드'
웹사이트에 공개해도 안전한 일반 손님용 출입증(Anon Key)과, 서버 관리자만 가지고 있어야 하는 마스터키(Secret Key)로 구분됩니다.

실시간 통신
실시간 동기화 (Realtime Sync)

비유: '0.1초 만에 똑같이 바뀌는 무선 쌍둥이 마법'
새로고침(F5)을 누르지 않아도 다른 컴퓨터나 스마트폰에서 데이터를 입력하면 내 화면에 0.1초 만에 스스로 글이 나타나는 실시간 스트리밍 기술.

브라우저 보관함
로컬스토리지 (localStorage)

비유: '내 책상 속 나만의 개인 서랍장'
서버 연결 없이 내 컴퓨터의 웹 브라우저 안에만 데이터를 보관하는 기술. 창을 닫거나 컴퓨터를 껐다 켜도 데이터가 안전하게 유지됩니다.

데이터 4대 동작
CRUD (크루드)

비유: '장보기 메모장의 4대 필수 기능'
새 글 쓰기(Create), 목록 보기(Read), 수정하기(Update), 삭제하기(Delete)의 영문 앞 글자를 딴 모든 데이터 앱의 핵심 기능.

테마 6

🛠️ 실무 개발, 품질 & 최종 배포 완성

초기 모델
프로토타입 (Prototype)

비유: '정식 출시 전 직접 만져보는 첫 번째 시제품 모형'
아이디어가 실제로 잘 동작하는지 빠르게 확인하기 위해 최소한의 핵심 기능만 갖추어 클로드로 10분 만에 뽑아낸 1차 결과물.

인터넷 주소
도메인 & DNS (Domain)

비유: '외우기 힘든 숫자 좌표 대신 부르는 우리 집 문패 주소'
외우기 힘든 서버 IP 숫자 대신 사람들이 쉽게 기억하도록 만든 친절한 웹 주소 (예: naver.com, my-project.vercel.app).

오류 잡기
디버깅 (Debugging)

비유: '달콤한 과일에 숨은 벌레(버그)를 돋보기로 잡아내기'
코드가 원하는 대로 동작하지 않을 때, 오타나 논리적 오류를 찾아내어 클로드에게 해결책을 물어보고 정상 작동하도록 고치는 과정.

코드 정리 정돈
리팩토링 (Refactoring)

비유: '집 외관은 그대로 두고 방 안을 깔끔하게 봄맞이 대청소하기'
화면이나 기능 결과는 똑같이 유지하면서, 내부 코드의 가독성을 높이고 불필요한 군더더기를 제거하여 관리하기 쉽게 다듬는 작업.

브라우저 호환성
크로스 브라우징 (Cross Browsing)

비유: '크롬, 사파리, 엣지 어디서 열어도 똑같이 예쁜 화면'
사용자가 구글 크롬, 애플 사파리, 네이버 웨일, 마이크로소프트 엣지 중 어떤 브라우저로 접속해도 화면 깨짐 없이 완벽하게 작동하도록 보증하는 기술.
